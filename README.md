# Cargo Dependency Visualizer

Практическая работа по конфигурационному управлению, вариант 12.
Приложение на Python для анализа зависимостей пакетов Cargo.

## Текущее состояние

Реализованы чтение и проверка параметров, загрузка данных из HTTP-индекса
Cargo и вывод всех объявленных прямых зависимостей выбранной версии.
Граф транзитивных зависимостей пока не строится.
Вывод настроек `ключ=значение` сохранён в коммите первого этапа.
При `--test-mode` приложение проверяет настройки и сообщает, что чтение
тестового графа будет добавлено на этапе 3. Пример JSON подготовлен заранее.

## Требования и подготовка

Нужен установленный Python 3. Внешние библиотеки не требуются.
Отдельная сборка не нужна. Команды ниже выполняются из папки проекта.

## Запуск

```powershell
python src/main.py --package serde --repository https://index.crates.io --version 1.0.0
```

На Windows можно использовать скрипт:

```powershell
.\run.bat --package serde --repository https://index.crates.io --version 1.0.0
```

Проверка настроек будущего тестового режима (сейчас завершается с кодом 1):

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --version 1.0.0 --filter B
```

Справка: `python src/main.py --help`.

## Настройки

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--package` | Имя пакета; в тестовом режиме заглавные буквы A-Z | Обязателен |
| `--repository` | URL HTTP(S) или путь к тестовому файлу | Обязателен |
| `--version` | Точная версия SemVer, например `1.2.3-beta.1` | Обязателен |
| `--test-mode` | Использовать тестовый файл вместо URL | Выключен |
| `--ascii` | Запросить вывод ASCII-дерева на этапе визуализации | Выключен |
| `--filter` | Исключать пакеты с подстрокой на этапе построения графа | Пустая строка |

Сейчас `--ascii` и `--filter` принимаются, но применяться будут на следующих
этапах. Второй этап выводит все объявленные прямые зависимости.
Указанный URL должен вести к корню HTTP-индекса Cargo, например
`https://index.crates.io`, а не к странице проекта или Git-репозиторию.
В выводе сохраняются требования к версиям, типы, optional и платформы.
Требования вида `^1.0` пока не разрешаются в конкретные версии.
При переименовании выводятся настоящее имя и псевдоним зависимости.

Коды завершения: 0 — успех или справка; 1 — ошибка получения данных либо
пока неподдерживаемый тестовый режим; 2 — ошибка параметров командной строки.
Причина ошибки выводится в stderr без трассировки исключения.

Пример ошибки версии:

```powershell
python src/main.py --package serde --repository https://index.crates.io --version 1.0
```

## Тестирование

```powershell
python -B -m unittest discover -s tests -v
```

Тесты проверяют настройки, ошибки параметров, загрузчик, чтение индекса,
выбор версии, сохранение условий зависимостей и вывод программы.
Сетевые ответы имитируются, доступ к интернету не требуется.

## Функции приложения

| Функция | Назначение |
| --- | --- |
| `validate_package` | Проверяет имя с учётом режима |
| `validate_version` | Проверяет формат точной версии |
| `validate_url` | Проверяет схему, наличие узла и порт URL |
| `validate_file` | Проверяет существование и доступность файла |
| `validate_filter` | Проверяет строку фильтра |
| `validate_args` | Запускает проверки значений параметров |
| `parse_args` | Читает параметры и обрабатывает ошибки |
| `format_dependency` | Подготавливает строку с именем и условиями зависимости |
| `print_dependencies` | Выводит прямые зависимости выбранной версии |
| `main` | Загружает зависимости, выводит результат и возвращает код завершения |

## Второй этап: работа с данными

Модуль `src/cargo_repository.py` загружает файл пакета из HTTP-индекса
Cargo, выбирает заданную версию и возвращает все объявленные прямые
зависимости вместе с их условиями. Модуль подключён к командной строке.
Диапазоны версий зависимостей пока не разрешаются в конкретные версии.
Типы dev/build, optional и ограничения платформы сохраняются без отбора.
При переименовании `name` содержит псевдоним, а `package` — настоящее имя.

| Функция | Назначение |
| --- | --- |
| `package_index_path` | Строит путь к файлу пакета в индексе |
| `package_index_url` | Строит полный HTTP-адрес файла |
| `download_package_index` | Загружает текст со всеми версиями пакета |
| `parse_index_record` | Читает строку JSON и проверяет основные поля |
| `find_package_version` | Выбирает пакет и версию, игнорируя метаданные сборки |
| `validate_dependency` | Проверяет основные поля зависимости |
| `get_direct_dependencies` | Загружает и возвращает прямые зависимости |
