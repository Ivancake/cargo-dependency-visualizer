# Cargo Dependency Visualizer

Практическая работа по конфигурационному управлению, вариант 12.
Приложение на Python для анализа зависимостей пакетов Cargo.

## Текущее состояние

Реализованы чтение и проверка параметров, загрузка данных из HTTP-индекса
Cargo и построение достижимого графа рекурсивным BFS. Для каждой зависимости
выбирается новейшая подходящая неотозванная версия. Вершины Cargo выводятся
как `имя@версия`. Тестовый граф читается из JSON.
Оба режима поддерживают фильтрацию и обработку циклов.
Добавлен обратный поиск через `--reverse`: по всему тестовому JSON или
внутри загруженного графа Cargo. Для обхода используется рекурсивный BFS.
Вывод настроек `ключ=значение` сохранён в коммите первого этапа.
При `--test-mode` граф читается из локального JSON, обращения к сети нет.

## Требования и подготовка

Нужен установленный Python 3. Внешние библиотеки не требуются.
Отдельная сборка не нужна. Команды ниже выполняются из папки проекта.

## Запуск

```powershell
python src/main.py --package serde --repository https://index.crates.io --version 1.0.0
```

На Windows можно использовать скрипт:

```powershell
.\run.bat --package serde --repository https://index.crates.io --version 1.0.0
```

Тестовый граф с фильтрацией пакета B:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --version 1.0.0 --filter B
```

Справка: `python src/main.py --help`.

## Настройки

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--package` | Имя пакета; в тестовом режиме заглавные буквы A-Z | Обязателен |
| `--repository` | URL HTTP(S) или путь к тестовому файлу | Обязателен |
| `--version` | Точная версия SemVer, например `1.2.3-beta.1` | Обязателен |
| `--test-mode` | Использовать тестовый файл вместо URL | Выключен |
| `--ascii` | Запросить вывод ASCII-дерева на этапе визуализации | Выключен |
| `--filter` | Исключать пакеты с подстрокой на этапе построения графа | Пустая строка |
| `--reverse` | Цель обратного поиска: `A` для JSON или `имя@версия` для Cargo | Не задан |

Сейчас `--ascii` принимается, но ASCII-дерево добавляется на этапе
визуализации. `--filter` применяется в обоих режимах. Поиск подстроки
учитывает регистр; в режиме Cargo имена пакетов приводятся к нижнему регистру.
В тестовом JSON нет версий: `--version` обязателен и проверяется как SemVer,
но на обход локального графа не влияет.
Указанный URL должен вести к корню HTTP-индекса Cargo, например
`https://index.crates.io`, а не к странице проекта или Git-репозиторию.
Записи индекса содержат требования к версиям, типы, optional и платформы.
В графе выводятся имена и выбранные версии пакетов. Требования вида `^1.0`
разрешаются в конкретные версии перед обходом.
При переименовании вершина использует настоящее имя пакета.

Коды завершения: 0 — успех или справка; 1 — ошибка получения или проверки
данных; 2 — ошибка параметров командной строки.
Причина ошибки выводится в stderr без трассировки исключения.

Пример ошибки версии:

```powershell
python src/main.py --package serde --repository https://index.crates.io --version 1.0
```

## Второй этап: работа с данными

Модуль `src/cargo_repository.py` загружает файл пакета из HTTP-индекса
Cargo, выбирает заданную версию и возвращает все объявленные прямые
зависимости вместе с их условиями. При построении графа функции загрузки
используются модулем `src/cargo_graph.py`.
Диапазоны версий разрешаются отдельным модулем при построении графа.
Типы dev/build, optional и ограничения платформы сохраняются без отбора.
При переименовании `name` содержит псевдоним, а `package` — настоящее имя.

| Функция | Назначение |
| --- | --- |
| `package_index_path` | Строит путь к файлу пакета в индексе |
| `package_index_url` | Строит полный HTTP-адрес файла |
| `download_package_index` | Загружает текст со всеми версиями пакета |
| `parse_index_record` | Читает строку JSON и проверяет основные поля |
| `find_package_version` | Выбирает пакет и версию, игнорируя метаданные сборки |
| `validate_dependency` | Проверяет основные поля зависимости |
| `get_direct_dependencies` | Загружает и возвращает прямые зависимости |

## Третий этап: чтение тестового графа

Модуль `src/test_repository.py` читает JSON следующего вида:

```json
{
  "A": ["B", "C"],
  "B": ["C"],
  "C": []
}
```

Ключ — имя пакета, значение — список его прямых зависимостей.
Имена состоят из заглавных латинских букв. Каждый пакет из списка
зависимостей должен быть описан отдельным ключом, в том числе с пустым
списком зависимостей. Циклы и ссылки на себя допускаются.
Повторяющиеся рёбра удаляются с сохранением порядка; повтор ключа считается
ошибкой. Поддерживаются UTF-8 и UTF-8 с BOM.

Загрузчик подключён к командной строке через `--test-mode`.

| Функция | Назначение |
| --- | --- |
| `unique_object` | Отклоняет повторяющиеся ключи JSON |
| `validate_node_name` | Проверяет имя тестового пакета |
| `validate_test_graph` | Проверяет связи и убирает повтор рёбер |
| `load_test_repository` | Читает и проверяет тестовый файл |

## Третий этап: рекурсивный BFS

Модуль `src/dependency_graph.py` строит достижимый граф по уровням.
Каждый рекурсивный вызов обрабатывает следующий уровень; уже обнаруженные
вершины повторно не загружаются. Циклические рёбра и ссылки на себя
сохраняются в результате. Порядок соседей соответствует данным загрузчика.

Непустой фильтр исключает пакеты, в имени которых есть указанная подстрока.
Поиск учитывает регистр. Обход через исключённую вершину прекращается,
но её потомок может попасть в результат по другой разрешённой ветке.
Если исключён корень, результат пустой. Пустой фильтр ничего не исключает.

`get_dependencies` — функция получения прямых зависимостей одной вершины.
Параметр `get_name` извлекает имя для фильтрации; по умолчанию используется
`str`. Для вершин Cargo `(имя, версия)` передаётся функция выбора имени.
Превышение глубины рекурсии возвращает понятную ошибку. Глобальный предел
рекурсии приложение не изменяет.

| Функция | Назначение |
| --- | --- |
| `build_dependency_graph` | Строит граф с помощью функции загрузки зависимостей |
| `build_test_dependency_graph` | Применяет BFS к проверенному тестовому словарю |

Обход подключён к тестовому режиму и реальным пакетам Cargo.

## Примеры тестового режима

Обычный граф:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --version 1.0.0
```

Граф с циклом A → B → C → A:

```powershell
.\run.bat --package A --repository examples/cycle.json --test-mode --version 1.0.0
```

Несвязанные группы пакетов (в результате остаются только A и B):

```powershell
.\run.bat --package A --repository examples/disconnected.json --test-mode --version 1.0.0
```

Формат вывода — по одной строке `пакет -> зависимости` в порядке BFS.
Все рёбра цикла сохраняются. Если фильтр исключает корень, выводится
сообщение о пустом графе.

## Третий этап: сравнение версий

Модуль `src/versions.py` разбирает точную версию SemVer и создаёт ключ
сортировки. Числовые части сравниваются как числа; предварительные версии
меньше стабильного выпуска с теми же тремя числами. Метаданные после `+`
на порядок не влияют. Модуль использует только стандартную библиотеку.

| Функция | Назначение |
| --- | --- |
| `parse_version` | Разбирает три числа версии и предварительный суффикс |
| `identifier_key` | Готовит числовой или текстовый идентификатор к сравнению |
| `prerelease_key` | Учитывает порядок предварительных и стабильных выпусков |
| `version_key` | Возвращает ключ для сортировки версий |
| `compare_versions` | Возвращает -1, 0 или 1 при сравнении двух версий |

## Третий этап: требования к версиям

Модуль `src/version_requirements.py` проверяет точную версию по требованию
Cargo. Поддерживаются `^`, `~`, `=`, `>`, `>=`, `<`, `<=`, подстановки
`*`/`x`/`X` и пересечение условий через запятую. Без оператора применяется
`^`; запись `=1.2.3` задаёт точную версию. Метаданные сборки не учитываются.

Предварительный выпуск допускается только при наличии условия с суффиксом
и теми же тремя числами версии. Пустое или ошибочное требование вызывает
`ValueError`. Разбор условия и получение зависимостей написаны самостоятельно;
внешние библиотеки для них не используются.

| Функция | Назначение |
| --- | --- |
| `read_components` | Читает числовые компоненты и проверяет порядок подстановок |
| `parse_partial` | Разбирает сокращённую или полную версию в условии |
| `parse_comparator` | Разбирает одно условие и его оператор |
| `parse_requirement` | Разбирает все условия через запятую |
| `compare_partial` | Сравнивает указанные части версии |
| `matches_tilde` | Проверяет оператор `~` |
| `matches_caret` | Проверяет оператор `^` |
| `matches_comparator` | Проверяет одно разобранное условие |
| `matches_parsed_requirement` | Применяет готовые условия к точной версии |
| `matches_requirement` | Проверяет версию по строке требования |

## Третий этап: выбор версии зависимости

Модуль `src/version_selection.py` читает записи одного пакета и выбирает
самую новую версию, удовлетворяющую требованию. Сравнение выполняется
по SemVer, порядок строк индекса не влияет на результат.
При автоматическом выборе отозванные версии (`yanked: true`) пропускаются.
Если подходящей версии нет, выводится ошибка с именем пакета и требованием.
Выбранная запись сохраняется целиком, включая зависимости и их условия.

Чтение индекса сохраняет и отозванные версии; их исключение происходит
только при автоматическом выборе. Повтор версии, в том числе с другими
метаданными сборки, считается ошибкой индекса. Флаг yanked проверяется
как логическое значение; отсутствие флага трактуется как false.

| Функция | Назначение |
| --- | --- |
| `record_is_yanked` | Проверяет флаг отзыва версии |
| `read_package_versions` | Читает и проверяет все записи одного пакета |
| `select_latest_version` | Выбирает новейшую подходящую неотозванную запись |
| `select_package_version` | Объединяет чтение индекса и выбор версии |

Выбор выполняется отдельно для каждой зависимости. Условия Cargo.lock
и согласование версий между ветками пока не учитываются.

## Третий этап: загрузчик Cargo и BFS

Модуль `src/cargo_graph.py` связывает загрузку индекса, выбор версий и
рекурсивный BFS. Вершина имеет вид `(имя, версия)`: разные версии одного
пакета сохраняются отдельно. Имена приводятся к нижнему регистру.

Класс `CargoRepository` хранит в памяти два кеша: проверенные записи всех
версий пакета и результат выбора по паре `(имя, требование)`.
Успешно прочитанный индекс скачивается один раз за обход. При ошибке данные
в кеш не записываются, поэтому повторная попытка загрузки допускается.

Фильтрация выполняется до загрузки индекса зависимости. Исключённый пакет
не вызывает сетевого запроса. При переименовании используется поле package.
Учитываются все объявленные виды зависимостей, включая optional/dev/build
и ограничения платформы; их активация по features пока не вычисляется.
Одинаковые рёбра между одной парой версий объединяются.

Обход поддерживает один HTTP-индекс. Непустой адрес другого реестра вызывает
понятную ошибку. Явно заданная версия корня может быть отозванной, но при
автоматическом выборе зависимостей yanked-версии пропускаются.

| Функция или метод | Назначение |
| --- | --- |
| `package_key` | Проверяет и нормализует имя пакета |
| `CargoRepository.__init__` | Сохраняет настройки и создаёт кеши |
| `CargoRepository.get_versions` | Загружает и кеширует записи пакета |
| `CargoRepository.get_exact` | Находит явно заданную версию |
| `CargoRepository.select` | Выбирает и кеширует подходящую версию |
| `CargoRepository.resolve_dependency` | Получает вершину зависимости |
| `CargoRepository.get_dependencies` | Возвращает соседей вершины для BFS |
| `build_cargo_dependency_graph` | Строит граф реальных пакетов |

Модуль подключён к обычному запуску через `run_cargo_mode`.
В выводе графа версии обозначаются как `имя@версия`, например
`helper@1.2.0`. Один пакет с разными версиями имеет несколько вершин.

## Четвёртый этап: обратные зависимости

Обратные зависимости — пакеты, которые зависят от выбранной цели напрямую
или через другие пакеты. Модуль `src/reverse_dependencies.py` разворачивает
рёбра и использует рекурсивный BFS из третьего этапа. Сам целевой пакет
исключается из ответа даже при цикле или ссылке на себя.

| Функция | Назначение |
| --- | --- |
| `reverse_graph` | Разворачивает рёбра, сохраняя вершины и порядок соседей |
| `find_reverse_dependencies` | Находит прямых и транзитивных потребителей |

Параметр `--reverse` принимает цель поиска. В режиме JSON поиск выполняется
по всему содержимому файла. `--package` остаётся обязательным и проверяется,
но не ограничивает обратный поиск достижимыми из него вершинами.

Пример с несколькими потребителями и транзитивными связями:

```powershell
.\run.bat --package A --repository examples/reverse.json --test-mode --version 1.0.0 --reverse D
```

```text
Обратные зависимости для D:
- B
- C
- X
- A
- Y
```

Проверка цикла:

```powershell
.\run.bat --package A --repository examples/cycle.json --test-mode --version 1.0.0 --reverse A
```

Проверка пакета без потребителей:

```powershell
.\run.bat --package A --repository examples/reverse.json --test-mode --version 1.0.0 --reverse Z
```

Проверка фильтра, исключающего X и путь через него к Y:

```powershell
.\run.bat --package A --repository examples/reverse.json --test-mode --version 1.0.0 --reverse D --filter X
```

В режиме Cargo `--package` и `--version` задают корень загружаемого графа.
Цель `--reverse` задаётся отдельно как `имя@точная_версия`. Обратный поиск
выполняется только внутри этого графа; весь внешний реестр не сканируется.
Область поиска явно указывается в выводе. Отсутствие цели в загруженном графе
считается ошибкой, а не отсутствием обратных зависимостей во всём реестре.
Метаданные сборки не влияют на равенство версий цели.

```powershell
.\run.bat --package lazy_static --repository https://index.crates.io --version 1.4.0 --reverse spin@0.5.2
```

Фильтр исключает вершины и прекращает обход через них. Потребитель может
сохраниться в ответе при наличии другой разрешённой ветки.
Если исключена сама цель, выводится отдельное сообщение.

## Ограничения анализа Cargo

В граф включаются все объявленные зависимости, включая optional, dev/build
и зависимости для разных платформ. Активация по features не вычисляется.
Выбор версии выполняется отдельно для каждого требования. Cargo.lock,
ограничения версии Rust, согласование версий между ветками и обратный поиск
совместимого набора версий пока не учитываются. Поэтому граф может отличаться
от результата штатного Cargo для конкретной сборки.
